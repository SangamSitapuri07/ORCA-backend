How to think about "winning odds" at SIH

⚡ The 5 filters used to pick these 12 (apply them to any PS):

  • Competition density — SIH shortlists & crowns winners per problem statement. A niche PS from an unglamorous ministry (Consumer Affairs, MoSPI, Petroleum, MoSJE) gets far fewer idea submissions than ISRO / MoES weather / "AI chatbot" PS. Same effort → 3–10× better odds.
  • Demo-ability in 36 hours — Judges reward a working live demo over architecture slides. Vision scans, live alerts, dashboards, maps and graphs photograph well.
  • Checklist-able scope — PS that list features (a, b, c…) let you tick every box visibly; vague research PS ("build a novel model") are risky.
  • Data availability — Public data / APIs / synthetic-but-realistic data you can generate yourself = no dependency on the ministry.
  • Innovation headroom — Room to add a differentiator (GenAI assistant, explainability, offline mode, multilingual voice) that other 6-member teams skipped.

✅ Execution playbook (whichever PS you lock)

  1. Decide by 28 Aug. Submissions close 20 Sept 2026; college internal hackathons happen earlier — finish your idea PPT at least a week before your SPOC's internal deadline.
  2. Check the live submission count for your 3 favorite PS on sih.gov.in right before locking in — if a Tier-A pick shows unusually heavy traffic, switch to your backup. Numbers beat opinions.
  3. Build the demo backwards: script the 3-minute judge demo first, then build only what it needs. Every feature must be visible on screen.
  4. One "nobody-else-has-this" feature (offline mode, one-regional-language voice input, citation-verified answers, real-data feed) is worth ten generic ones.
  5. Requirements traceability slide: PS asks (a)–(h) → show each one checked off with a 5-second screen shot. Judges score against the PS literally.
  6. Name the dataset & evaluation metric in your submission (accuracy, PSNR, precision/recall) — quantify or judges assume it doesn't work.
